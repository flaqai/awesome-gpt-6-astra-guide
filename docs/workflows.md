# 六套从目标到成果的工作流

[中文首页](../README_zh.md) · [English](../README.md) · [先看案例](cases.md)

以下是本仓库原创练习模板，不是作者提示词。在 ChatGPT / Work、Codex 客户端或 Codex CLI 选择 Astra 后，直接粘贴使用；复制前替换方括号里的材料。时间取决于任务、工具和账号；没有“一个提示词必定完成”的保证。

通用做法：**材料 → 最小版本 → 实际检查 → 定向修改 → 可编辑交付**。网页、3D、视频需要相应开发或创作环境；只有文字 API 时，先用它生成方案与代码。

<a id="workflow-web"></a>

## 01 · 从参考截图到交互页面

**准备**：一张有权使用的截图、目标屏幕尺寸、现有项目。新手先选单页面，不接登录和支付。

```text
请根据附件的布局特点，为[品牌/主题]制作一个单页网站。
目标用户：[用户]，主要行动：[预约/浏览作品/下载资料]。
从目标用户与内容重新设计信息层级、版式和交互，使用自己的文字与素材。
首版包括：标题区、三个案例卡片、一个可工作的筛选控件。
技术：优先使用当前项目已有技术；如是空目录，选择简单方案并说明。
验收：桌面和 390px 宽度都不横向溢出；筛选真的改变列表；按钮可用键盘操作。
交付：源码、启动步骤、桌面和手机实际截图，以及做过的检查。
```

**迭代**：“手机截图中第二张卡片的按钮超出边界，请修复并重新截图。”

**直接使用**：在 ChatGPT 或 Codex 客户端附上截图并发送上述指令；在 Codex 项目里继续实现。CLI 可用 `codex -m gpt-6-astra -i [截图路径]` 附图开始。

## 02 · 从游戏点子到一个可玩关卡

**准备**：控制方式、胜负条件、目标设备；先不要多人联网。

```text
制作一个原创单人小游戏：[例如移动角色收集五颗星星]。
首版仅一关，支持开始、暂停、重开。
先用简单几何图形实现移动、碰撞和胜利条件，再改善外观。
不要引用没有授权的角色、音乐或贴图。
验收：能够完成一局；暂停时状态不变；重开清空分数；说明键盘操作。
交付：源文件、运行方式、游戏截图、已知限制。
```

**检查顺序**：先完整玩一局，再连续重开，最后尝试边界、碰撞和失去窗口焦点。游戏规则稳定后，再让 Astra 加粒子、音效或 3D。

**继续学习**：先用 [原创验收报告](original-lab.md) 的显式规则思路定义游戏状态，再编写自己的重置和计分逻辑。外部作品只作 [延伸阅读](community-references.md)。

## 03 · 参考图到可编辑 3D 资产

**准备**：Blender、参考图、比例尺寸；若依赖代理执行，要让环境可以运行 Blender 或操作其界面。

```text
根据参考图建立[物体]的可编辑 Blender 场景。
先识别主要形体和遮挡关系；看不见的背面标成合理推测。
第一阶段只做粗模，用独立物体区分部件并命名。
生成正面、侧面、透视三张检查图，再修比例、添加材质与灯光。
交付：[名称].blend、预览图、所用脚本及重新渲染步骤。
验收：部件可单独编辑；重新打开工程不缺素材；渲染能复现。
```

**迭代**：“轮径看起来过小，请对照侧面图调整，保留已完成的材质。”不要一开始就要求数千物体，先让主体比例成立。

**拓展到像素画**：将交付物改为可编辑图层与 PNG，并约束尺寸和调色板。不同创作软件需要不同工具连接，不能仅改文件扩展名。

## 04 · 已有素材到短视频

**准备**：五段授权素材、目标时长、画幅、字幕文本、音乐授权。需要剪辑软件或可执行的渲染/剪辑工具。

```text
使用指定目录中的素材制作一支 15 秒[主题]短视频。
画幅：9:16；结构：3 秒开场、9 秒内容、3 秒结束标题。
先列出素材文件、建议入点/出点和字幕，再制作粗剪。
声音只使用已提供并确认可用的素材。
交付：可编辑工程、素材引用清单、最终 MP4、三个关键帧截图。
验收：字幕在安全区域内；无意外黑帧；首尾完整；声音不突然截断。
```

**迭代**：“第 6 秒转场太快，把该镜头延长半秒，并保持总时长。”Astra 在这里负责规划、代码或软件操作；素材生成、编码和声音由对应工具完成。

<a id="workflow-research"></a>

## 05 · 从问题到有来源的研究简报

**准备**：明确的问题、时间范围、允许来源、希望比较的指标。

```text
研究[明确问题]，时间范围为[起止日期]。
优先查官方文档、原始论文和公开数据。
每个关键结论紧跟来源链接；区分来源事实、你的推断和仍缺的信息。
交付：一页结论、三项比较、证据表、下一步待验证问题。
不要用多个转载网页冒充独立证据；找不到的资料明确写出。
```

**直接使用**：在 ChatGPT Work 或具备搜索工具的 Codex 任务中发送研究问题，要求实际搜索并附来源。验收时打开三条引用，确认它们支持对应结论。

**科学可视化扩展**：先确认模型方程、单位、数据来源，再让 Astra 编写可调参数模拟；使用解析解、守恒量或步长对照验收。动画好看并不证明科学结论正确。

<a id="workflow-review"></a>

## 06 · 代码审查与修复

**准备**：仓库、可重复的错误描述、预期结果。项目中已有说明与检查命令优先。

```text
请定位并修复：[触发步骤、实际结果、预期结果]。
先找出相关代码路径，说明证据，再做范围最小的修复。
若缺少普通环境细节，请从仓库配置判断；无法确认时说明假设。
只运行与变更相关的检查；不要顺手重构无关模块。
交付：修改文件、修复原因、实际验证结果、仍未验证的范围。
验收：原触发步骤不再失败，已有相关行为仍然成立。
```

**迭代**：“修复了空输入，但中文输入仍报错，这是新的复现步骤……”提供具体证据通常比要求“再认真检查”更有效。
